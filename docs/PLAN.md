# План ядра Agon Light для Karabas Go / Mini / Mini G

Цель: Agon Light / Console8 на платах Karabas (XC6SLX25, ISE 14.7): eZ80F92 на 18,432 МГц, 512 КБ внешней RAM, SD-карта, на которой работает MOS, и VDP (видео, звук, клавиатура и мышь), совместимый с прошивкой Console8. Должны запускаться родные MOS, BBC BASIC (ADL) и программы с SD-карты Agon.

## Что изучено (2026-11-18)

### Железо Agon (по AgDev Agon-HW.md, проверить по исходникам MOS)

- eZ80F92, 18,432 МГц; флеш 128 КБ на кристалле (MOS), SRAM 8 КБ на кристалле, внешняя RAM 512 КБ.
- UART0 ↔ ESP32 VDP: 1 152 000 бод (запасной вариант 384 000), RTS/CTS. Поток команд VDU в стиле BBC Micro, обратно — клавиши, мышь, ответы на запросы.
- SD-карта по SPI eZ80, FatFS в MOS.
- GPIO PB / PC / PD; PB1 от VDP (VSYNC); таймеры PRT, I2C, RTC без кварца (время приходит от VDP).
- На оригинале VDP генерирует видео ESP32 (DMA I2S → резисторный ЦАП VGA), звук через ЦАП ESP32, PS/2 клавиатура и мышь на ESP32.

**Ни одного Agon на ПЛИС и ни одного VDP на ПЛИС нет** (поиск GitHub и веба 2026-11-18). Главная трудность ядра — VDP. ESP32 на наших платах нет (Wi-Fi — ESP8266).

## Варианты VDP

1. **Софт-процессор в ПЛИС с настоящей прошивкой VDP.** VexRiscv (rv32im, как в core-doom), код и куча в SDRAM, кадр в SRAM или SDRAM, развёртка и палитра в RTL. agon-vdp + vdp-gl собираются с прослойкой по образцу userspace-vdp-gl (там уже есть замена ESP32 и FreeRTOS). Плюс: полная совместимость с VDP Console8 и его обновлениями. Риски: C++17 и потоки в прослойке, объём кода и кучи, скорость (ESP32 — два ядра по 240 МГц, у нас одно около 80 МГц; зато развёртку делает железо, а не процессор).
2. **VDP в RTL (подмножество).** Текст, режимы экрана, графические примитивы, битмапы, спрайты, звук — аппаратно. Плюс: скорость и мало памяти. Минус: огромный протокол VDU (буферизованные команды и т. п.), совместимость только частичная.
3. **Смесь:** развёртка, спрайты, звук и блиттер в RTL, разбор протокола на маленьком процессоре.

Выбор — по замерам Ф0.

## Решения

- 2026-11-18 (пользователь): делаем Agon; приватный репо `karabas-go-core-agon`.
- 2026-11-18 (пользователь): ядро eZ80 своё — расширение BSD-ного T80 (Daniel Wallner) до eZ80 (ADL, 24 бита, MBASE, новые команды) под шину eZ80F92. MSXnano-eZ80 и эмуляторы — только эталоны, их код не берём.
- 2026-11-18 (пользователь, после Ф0): VDP — вариант 1, настоящая прошивка VDP на VexRiscv + наши патчи скорости; развёртка, FIFO звука и прочая обвязка в RTL. Блиттер в RTL — потом, по надобности.

## Ф0. Замеры (ветка f0-measure)

1. **T80 на XC6SLX25.** XST чистого T80 как нижняя граница (LUT, Fmax) и оценка прироста от ADL. Нужно 18,432 МГц (лучше с запасом на турбо).
2. **Эталон CPU.** `agon-ez80-emulator` → трасса; сравнение с RTL покомандно в симуляции. Критерий: MOS в симуляции доходит до обмена с VDP.
3. **Сборка VDP для rv32im.** agon-vdp + userspace-vdp-gl для голого rv32im: собирается ли, размер кода и кучи.
4. **Нагрузка VDP.** На ISS из core-doom: инструкций на типовые действия (вывод и прокрутка текста, смена режима, PLOT, битмапы) против бюджета VexRiscv 80 МГц.
5. **Сводка ёмкости:** eZ80 + периферия F92 + VexRiscv + видео + модули kg против LX25.

### Результаты Ф0 (2026-11-18)

**1. T80** (MiSTer v350, копия из core-cpc), XST XC6SLX25-2 отдельно, `-iobuf NO`: 1879 LUT (12 %), 414 FF, 76 МГц. eZ80 (24-битные регистры и PC, MBASE, новые команды) — оценка в 1,5–2 раза больше: 3–4 тыс. LUT.

**3. VDP собирается под голый rv32im и работает.** `src/vdp/`: agon-vdp (Console8 2.16.0, коммит fab-agon-emulator 1056ee3) + vdp-gl из userspace-vdp-gl, xPack riscv-none-elf-gcc 15.2, `-std=gnu++17`, полный newlib (в nano нет `swprintf` для локалей libstdc++). Что пришлось заменить:
- `std::thread` / `std::mutex` / `lock_guard` / `unique_lock` / `this_thread::sleep_for` — свои `compat/thread`, `compat/mutex` поверх кооперативного планировщика `coop.c` (задачи: processLoop, аудио, мигание курсора терминала, наши vblank и снимки); `<dirent.h>` — заглушка.
- `Serial2` (UART0 к eZ80) — свой `kg_serial.cpp` прямо на MMIO; пустой приём уступает управление (VDP ждёт байты в циклах опроса).
- vblank: счётчик кадров `MMIO_FRAME` → задача ставит `vblankSignal`; неудачный 1-байтовый CAS (`waitVblank` крутит его) уступает управление. Без A-расширения: `__atomic_compare_exchange_1` и `__dso_handle` в `syscalls.c`.
- Код 1,3 МБ (из них ~300 КБ локали libstdc++), куча и стек — в SDRAM.

ISS (`src/sim/iss.cpp`, из core-doom): поток байт eZ80 по UART, лог ответов VDP, снимки экрана. VDP грузится, отвечает на general poll, присылает режим (640×480, 80×60, 16 цветов), рисует строку версии и текст.

**4. Нагрузка** (`src/sim/run_f0.sh` + `mkstream.py`, байты все сразу, прогон останавливается по ответу VDP на последний general poll; `model.py` — модель тактов core-doom, откалиброванная на Verilator: такты = 1,5 · инструкции + 28 · (промахи I$ + D$), SDRAM на частоте CPU). Весь набор — 2,6 с.

- Текст: ~9,6 КБ/с при 16К/16К (4К/4К — 6,5 КБ/с). Профиль text0: ~60 % — вывод глифа попиксельно через `std::function` (`genericDrawGlyph_light`, `VGA16_SETPIXELINROW`), ~10 % — программный `double` (`__muldf3`, `__divdf3`). UART даёт до 115 КБ/с; ESP32 (Xtensa 240 МГц, тот же код) по грубой оценке в 3–4 раза быстрее.
- Игры: 16 спрайтов — ~3 мс на кадр, битмап 16×16 в режиме 8 — ~0,3 мс: в кадр 16,7 мс укладывается.
- Звук (задача заполняет FIFO 16384 Гц из `SoundGenerator::getSample()`): 3 канала стоят ~3 % (textaudio против text0). Смена режима держит процессор ~70 мс без уступки — FIFO звука в RTL нужен на 4К сэмплов (~250 мс, 2 RAMB16). Пока поток полон, VDP не уступает: `available()` уступает раз в 1 мс.
- Стеки задач: максимум 1,6 КБ (processLoop) из 16 КБ; узнаём по заполнению шаблоном, `coop_spawn` без места — выход с кодом 90.
- Кэши: 16К + 16К = 16 RAMB16 из 52.

**Развёртка (что нужно RTL).** Контроллеры vdp-gl для Agon: `VGA2/4/8/16Controller` (палитровые на 2 / 4 / 8 / 16 цветов, упаковку пикселей в байте уточнить по `*_SETPIXELINROW`, палитра RGB222 из 64 цветов, смена палитры по строкам — списки палитр) и `VGA64Controller` (байт на пиксель, RGB222 + биты синхро). Кадр — пулы памяти (`allocateViewPort`) и таблица указателей строк `m_viewPortVisible[y]`; прокрутка меняет местами указатели строк, двойной буфер — таблицы (`swapBuffers`). Значит, развёртка на каждой строке читает указатель из таблицы, потом строку; прошивка сообщает RTL адрес таблицы, формат, ширину, палитру (наш хук в задаче vblank). Поток: 640×480×4 бит × 60 Гц = 9,2 МБ/с, 64 цвета (байт на пиксель) — до 18,4 МБ/с. Кадр лучше держать в SRAM (отдельная шина, 4 МБ): `heap_caps_malloc` пулов кадра направить туда, код и кучу оставить в SDRAM.

**SD-карта.** На Go, Mini и Mini G `SD_CS_N` / `SD_DI` / `SD_DO` / `SD_CLK` / `SD_DET_N` выведены на ПЛИС (L4 / L7 / M7 / L8 / M6, ucf core-tsconf и core-next): MOS работает с картой по SPI eZ80 напрямую.

**UART к eZ80.** В ISS канал без потерь; на плате уровень FIFO приёма VDP управляет CTS к eZ80 (MOS ждёт CTS).

**Ускорения VDP (патчи к vdp-gl, `src/vdp/patches/`, по одному на файл, накладываются на копию при сборке; помечены `karabas:`).** Проверка: снимки экрана 19 потоков побайтно равны снимкам сборки без патчей (`make GL_PATCHED= B=build-nopatch`), игровые снимки и текст проверены глазами. Покрытие: быстрый путь глифа — текст в режимах 0 / 1 / 2 / 3 / 8 (2 / 4 / 16 / 64 цвета); общий путь с инлайн-записью — `VDU 5` в нечётных позициях и с обрезкой по графическому окну (`gtext0/1/2/8`). Не проверено: инверсный текст, списки палитр по строкам. VGA8 (8 цветов) в Agon не используется: в таблице режимов нет 8-цветных.
- `drawGlyph` всех палитровых контроллеров: глиф 8 точек целиком внутри окна и с выровненным X пишется байтами по таблице (2 / 4 / 16 / 64 цвета), остальные глифы `PaintMode::Set` — общий путь с инлайн-записью пикселя вместо `std::function`.
- `rgb222_to_hsv`: 64 результата считаются один раз (тем же кодом) — таблица палитры пересчитывается при каждой смене режима и палитры (~1100 вызовов `double`).
- `-O3` хуже `-O2` (код больше, промахов больше); нагрузка чисто процессорная (время ∝ 1 / частота).

**2. eZ80F92, что нужно MOS** (по `agon-ez80-emulator/src/agon_machine.rs` fab-agon-emulator, который грузит настоящую MOS):
- Память: флеш 128 КБ по адресу `FLASH_ADDR_U` (порт F7) << 16, такты ожидания `FLASH_CTRL` (F8, биты 7:5); SRAM 8 КБ на кристалле по `{RAM_ADDR_U (B5)}:E000`, включение `RAM_CTL` (B4); внешняя RAM 512 КБ в окне CS0 (`CS0_LBR` / `CS0_UBR`, A8 / A9): адрес идёт на SRAM без вычитания (A0–A18), CS1–CS3 (AB–B3) MOS пишет, но не использует. Чтение мимо всего — F5.
- Порты (16-битный адрес, старший байт 00): PRT0–5 (80–91: CTL, reload / счётчик L / H), GPIO B / C / D (9A–A5: DR, DDR, ALT1, ALT2), SPI (B8–BC: BRG L / H, CTL, SR, TSR / RBR) — SD-карта, UART0 (C0–C7, 16550-подобный: RBR / THR / BRG, IER, IIR / FCTL, LCTL, MCTL, LSR, MSR, SPR) — к VDP, I2C (C8–CD), UART1 (D0–D7) — в MOS не используется.
- Прерывания: векторы `{I, IVECT}` (UART0 18, UART1 1A, PRT, порт B: PB1 = vsync от VDP).
- Флеш 128 КБ в BRAM не влезает (52 RAMB16 = 104 КБ): MOS — в SRAM платы (из `.kg`), там же внешняя RAM 512 КБ.
- Эталон для покомандной сверки RTL: этот же эмулятор (крейт `tomm/ez80`, ZEXALL проходит; режим eZ80 «экспериментальный»). Нужен Rust (cargo) — не установлен.

**Итог Ф0 (2026-11-18): вариант 1 (настоящая прошивка VDP, «Agon Platform VDP 2.16.0», на VexRiscv) — предлагаю его.** Та же прошивка, свои только обвязка и патчи скорости с проверкой по снимкам. Режимы Agon (`agon_screen.h`): 640×480, 640×240, 320×240, 320×200@70 Гц, 800×600, 1024×768, 512×384, 640×512, 640×256, по 2 / 4 / 16 / 64 цвета, плюс двойная буферизация (режимы 129+). В Ф1 решить: свой тайминг на каждый режим или масштабирование в один выходной (как у других ядер).

Осталось в Ф0: эталон eZ80 (после установки Rust; нужен уже к RTL eZ80), сборка VexRiscv 16К (после Java + sbt; не блокирует).
